安全の作り

狙われやすい入口をはじめから置かない作りで、ホームページをお作りしています。あわせて、会社のメール・パソコン・アカウントの守りも、画面を見ながらご一緒します。はじめの30分（ホームページの https と、偽メールの設定の点検）は無料です。ご相談は、お届けした手紙への返信に「30分の点検を」とだけ書いていただければ大丈夫です。

弱いサイトを探す手間が、
AIで減ってきています

穴のあるサイトを機械で自動的に探して回る攻撃は、ずっと前からあります。そこにAIが加わって、攻撃の準備にかかる手間が小さくなってきました。

IPA（情報処理推進機構）が2026年1月に出した「情報セキュリティ10大脅威 2026」の組織向けの一覧では、「AIの利用をめぐるサイバーリスク」が初めて入り、3位でした。説明には、AIの悪用で攻撃がしやすくなり、手口も巧妙になることが挙げられています。同じ一覧の4位は「システムの脆弱性を悪用した攻撃」です。脆弱性は、ソフトの欠陥でできた穴のことです。

機械で探す側は、お店や会社の大きさではなく、穴があるかどうかを見ています。「うちは狙われない」とは言いにくくなりました。

よくある狙われ方と、見本の作り

見本は、文字と絵だけでできたページです。開くたびにサーバーの上で何かを動かす仕組みを持たないので、入口になりやすい所を、はじめから置いていません。よくある狙われ方と並べると、こうなります。

入口の数で比べると

狙われる入口WordPressなどのブログ型この見本（静的なページ）
ログイン画面・管理画面ありなし
サーバーの上で動くプログラム（PHPなど）ありなし
情報をためる場所（データベース）ありなし
追加の部品（プラグイン）入れた数だけなし
置き場所・ドメインのアカウントありあり（持ち主の名義で持ち、二段階認証を付けていただきます）
更新を続ける手間本体とプラグインを、ずっと中身を変えるときだけ

WordPressの列の「あり」は、穴が見つかるたびに直し続ける所です。この見本では、そこがはじめからありません。残るのはアカウントだけなので、そこを二段階認証で守ります。ご自分で記事を書き足したいなど、WordPressにする理由があるときはWordPressでもお作りします。そのときは、更新とバックアップの見守りまで引き受けます。

よくある狙われ方

古いWordPressや、プラグインの穴

ブログ型の仕組み（WordPressなど）は便利ですが、本体や追加の部品（プラグイン）の更新が遅れると、知られた穴から入られます。穴が知れ渡ると、それを探して回る動きがすぐに始まります。

この見本では

WordPressもプラグインも使っていません。サーバーの上で動く仕組みがないので、更新を忘れて穴になる部品がありません。

よくある狙われ方

問い合わせフォームの悪用

入力欄に細工した文字を送り込んでお客さんの情報を抜き出したり、迷惑メールを送る中継に使ったりします。

この見本では

送れる入力欄も、情報をためる場所（データベース）もありません。ご予約や問い合わせは、電話やメールのボタン（お店によってはLINEや予約サービスへ進むボタン）で受ける形です。フォームが要るときは、https の送り先とスパム対策を付け、その送り先だけを許す設定にします。工場の見本にある見積もりの欄は見た目の見本で、送れないように作ってあります。

よくある狙われ方

よそから読み込む部品の乗っ取り

アクセス解析や広告、地図、文字の形（フォント）などを、よそのサーバーから読み込んでいるページはたくさんあります。読み込み元が乗っ取られると、悪いプログラムがページに混ざります。

この見本では

よそからは何も読み込んでいません。そのうえで「このサイトの見た目の指定と画像のほかは読み込まない。プログラムは一切動かさない」という決まりをページ自体に書いてあります（CSPという仕組みです）。万一、ページに悪いプログラムが紛れ込んでも、ブラウザが動かさずに止めます（ファイルそのものを書き換えられたときは止められません。そこはアカウントの守りの出番で、下に書きます）。

よくある狙われ方

管理画面のパスワード破り

ホームページの管理用のログイン画面に、よく使われるパスワードを次々に試して入り込みます。

この見本では

ページの中にログイン画面がありません。書き換えは、手元でファイルを直して置き直す形です。入り込める所は、ページを置いている場所とドメインのアカウントに絞られます。そこは二段階認証で守っていただきます（下に書きます）。

よくある狙われ方

通信のすり替えや、よそのページへの埋め込み

鍵のない通信（http）の途中で中身を書き換えたり、ページをよそのページに透明に重ねて押し間違いを誘ったりする手口です。

この見本では

お渡しするときは、置き場所（Cloudflare Pagesなど）の設定で「必ず鍵つきの通信（https）で開く」「よそのページに埋め込ませない」という決まりを付けます。いま見本を置いている所はこの設定を付けられないため、見本では埋め込みを止める決まりが効いていません。

それでも「絶対に安全」とは言えません

ここまで書いたのは、入口を減らす作りです。攻撃そのものをなくす作りではありません。残る入口でいちばん大きいのは、ページよりも、ページを置いている場所と、お店や会社のアカウントです。ここは持ち主にしかできない守りなので、次のことをお願いしています（最後の1つは、私の側の約束です）。

  1. ドメインと置き場所は、お店・会社の名義でドメインは、ネットの上の住所にあたる名前です。置き場所と一緒にお店・会社の名義と、そのメールアドレスで持っていただき、二段階認証（パスワードに加えて、スマホでの確認を求める設定）を付けます。ドメインには、勝手によそへ移されないための「移管ロック」をかけ、更新を忘れて手放さないよう「自動更新」にしておきます。置き場所を変えたりやめたりしたときは、古い向き先の設定（DNS）を残さず消します。
  2. メールやLINEのアカウントもページが無事でも、メールやLINEが乗っ取られると、お客さんや取引先に偽の連絡が届いてしまいます。こちらにも二段階認証などの、ログインの確認を強くする設定をおすすめします。
  3. Googleのビジネスプロフィールも地図や検索に出るお店や会社の情報も、乗っ取られると電話番号や営業時間を書き換えられます。お店・会社のアカウントで持ち、二段階認証を付けていただきます。
  4. パスワードは預かりませんお手伝いが要るときは、お店・会社のアカウントに私を招いていただき、終わったら外してもらいます。招く仕組みのないサービスでは、画面を共有しながらご担当の方に操作していただきます。どちらの形でも、パスワードを私が知らないまま進められます。私の側でも、作業に使うアカウントには二段階認証を付けています。

もし「ページの中身が変わっている」「知らない連絡が出回っている」と気づいたら、まずパスワードを変えて、すぐにご連絡ください。お渡ししたときと同じファイルを手元に残しておくので、元の形にすぐ戻せます。

ネット予約やカード払いは、専門のサービスに

ネット予約やカード払いの画面を、このページの中に自前で作ることはしません。お客さんの名前やカードの番号を預かる所は、それを守ることを仕事にしている会社のサービスに任せる方が安全だと考えています。

すでにお使いの予約サービスやネットショップがあれば、そこへ進むボタンを置きます。お客さんが入れた情報は、このページを通らずに、そのサービスへ直接届きます。

ホームページの外の守り

会社の中の守りも、
画面共有でお手伝いします

ホームページのほかに、メール・パソコン・社員の方の備えも見ています。

ページを堅くしても、会社のメールやパソコン、アカウントが入口になることがあります。IPAの「情報セキュリティ10大脅威 2026」の組織向けの1位は、データを人質に取る「ランサム攻撃による被害」でした。入口になりやすいのは、偽のメールや、更新していない機器、使い回したパスワードです。ホームページと同じ考え方で、入口を一つずつ減らすお手伝いをしています。

1

偽メール対策の点検と設定（SPF・DKIM・DMARC）

会社のメールアドレス（@より後ろ）をかたった偽メールを、受け取る側で見分けて止めてもらうための設定です。SPFとDMARCが入っているかどうかは、誰でも見られる公開の記録（DNS）から確かめられます（DKIMは、届いたメールを一緒に見て確かめます）。今の設定を一緒に見て、会社から送っているサービス（会社のメール、請求書や予約の送信など）を洗い出し、DKIMを付け、DMARCを「報告を見るだけ」から段階を追って「止める」へ進めます。似た綴りの別のアドレスや、表示名だけを偽ったメールはこの設定では止められないため、勉強会で見分け方をお伝えします。

2

SECURITY ACTION の宣言と、自社診断の付き添い

IPAの「SECURITY ACTION」は、中小企業が情報セキュリティに取り組むことを自ら宣言する制度で、デジタル化・AI導入補助金（旧IT導入補助金）の申請の要件にもなっています。2026年4月から、申し込みはGビズID（プライムかメンバーのアカウント）でログインする新しい仕組みに変わりました。IPAの「5分でできる！情報セキュリティ自社診断」を一緒に答え、直す順番を1枚にまとめ、宣言の手続きは、画面共有で横についてお手伝いします。補助金の申請そのものの代行はしません。

3

パソコンとアカウントの点検

更新が止まっているパソコンはないか、辞めた方のアカウントが残っていないか、共有フォルダが誰にでも見えていないか。こうした所をチェック表で一緒に見て、直す順番を1枚にしてお渡しします。学校などのパソコンの保守や開発に5年ほど携わってきたので、つまずきやすい所の見当はつきます。

4

社員の方向けの短い勉強会

オンラインで30〜45分。偽メール、偽の請求書、画面に警告を出して電話をかけさせる「サポート詐欺」、ランサム攻撃の入口になりやすい場面を、実際の画面の例で見ていきます。最後に「怪しいと思ったら誰に言うか」を決めて終わります。

進め方はオンラインの画面共有で、操作はご担当の方にお願いします。パスワードやGビズIDは預かりません。はじめの30分（ホームページの https と、偽メールの設定の点検）は無料で、そのあとはお見積もりのうえで進めます。ご相談は、手紙やメールへの返信でどうぞ。

確かめていること

見本を直すたびに、ブラウザの開発者用の画面で、決まりに反した読み込みが1件も出ていないことを確かめています。お渡しするときは、公開したあとに外の点検サービスでも、設定がきちんと届いているかを見ます。

お渡ししたあとの保守は、書き換えの代行（月6,000円）に入っています。毎月1回、証明書とドメインの期限、安全のための設定、ページが書き換えられていないかを確かめてご報告します。

あわせて平日は毎日、国の窓口（IPA）などが出すソフトの穴（脆弱性）の知らせと、置き場所やドメインの会社のお知らせを確かめます。お預かりしたサイトに関わる危ないものは月1回を待たずにご連絡し、見つけてから1営業日以内に手当てを始めます（静的なページはサーバーで動く部品が無いので、当てはまることはまれです）。

専門の方へ（設定の中身）
考え方
サーバーの上で動く仕組み（PHP・データベース・ログイン画面・管理画面・プラグイン）を置かず、ブラウザの中でもスクリプトを動かしません。CSPとヘッダーは、それでも何か紛れ込んだときに止める、念のためのもう一枚です。
ページの中（meta）のCSP
default-src 'none'; style-src 'self'; img-src 'self'; font-src 'self'; base-uri 'none'; form-action 'none'; upgrade-insecure-requests
default-src 'none' を土台にして、許す物だけを足しています。script-src・object-src・connect-src・frame-src などは書いていなくても 'none' として扱われるため、スクリプト、<object>・<iframe> での埋め込み、スクリプトからの通信（fetch など）は止まります（リンクを押して移る先は CSP の対象外です）。base-uri 'none' で <base> の書き換えを、form-action 'none' で送信先のすり替えを止めます。upgrade-insecure-requests は、ページの中の http の読み込みを https に直すものです（http で開かれたページ自体を https に移すのは、置き場所のリダイレクトとHSTSの役目です）。
meta とヘッダーは、両方使います
同じCSPを、meta と置き場所のヘッダーの両方に書きます。frame-ancestors は meta では効かないため、ヘッダーの側にだけ足します。片方を緩めても、もう片方が止めます。変えるときは2か所を同時に直します。
お渡しのとき、置き場所（Cloudflare Pages・Netlify）の _headers で付けるもの
Content-Security-Policy（上のCSP ＋ frame-ancestors 'none'）／Strict-Transport-Security: max-age=31536000／X-Content-Type-Options: nosniff／X-Frame-Options: DENY／Referrer-Policy: strict-origin-when-cross-origin／Permissions-Policy: camera=(), microphone=(), geolocation=(), payment=(), usb=()／Cross-Origin-Opener-Policy: same-origin／Cross-Origin-Resource-Policy: same-origin
HSTSの includeSubDomains は、そのドメインの下で動いているほかのサービス（メール・予約システム・社内の機器など）が http のまま動いていないかを確かめてから足します。
いまの見本の置き場所（GitHub Pages）でできないこと
ヘッダーを自分で付けられないため、見本では meta のCSPだけで守っています。そのため、よそのページへの埋め込みを止める決まり（frame-ancestors・X-Frame-Options）は見本では効いていません。見本の入力欄は送れない作り（form-action 'none'）なので、害は小さくしてあります。
フォームや地図を足すとき
フォームは、迷惑送信を防ぐ仕組み（Cloudflare Turnstile など）を持つ送信サービスを使い、form-action にその送り先だけを足します。Turnstile を使うときは script-src と frame-src に https://challenges.cloudflare.com だけを足します（そのページだけ「スクリプトなし」ではなくなります）。地図は「地図を開く」リンクを基本にし、埋め込むときは frame-src に https://www.google.com だけを足します。
ドメイン・DNS・メール
ドメインは御社の名義で取り、登録先のアカウントに二段階認証、移管ロック、自動更新を付けます。置き場所を変えたりやめたりしたときは、古い向き先のレコードを残さず消します（残すと、そのサブドメインを他人に乗っ取られる元になります）。メールはSPF・DKIMを整えたうえで、DMARCを p=none（報告を受けて送り元を洗い出す）→ p=quarantine → p=reject と段階を追って進め、報告の受け先（rua）を付けます。
そのほか
JavaScriptなし。style 属性やインラインのスクリプト・onclick などもないため、unsafe-inline を許していません。外のサーバーからは何も読み込みません（フォント・解析タグ・CDNもなし）。写真は同じサイトに置いた画像ファイルだけで、載せる前に撮影場所などの情報（Exif）を消し、顔・名札・図面が写っていないかを確かめます。
確かめ方
直すたびに、ブラウザの開発者ツールのコンソールで、CSPの違反が出ていないことを確かめます。お渡しのあとは、外の点検サービス（securityheaders.com など）で、ヘッダーが届いているかを見ます。お渡ししたときのファイルは手元に残し、書き換えに気づいたら、1営業日以内に手元の版から戻し始めます。書き換えの代行をご契約の間は、証明書とドメインの期限（RDAP、取れないものは WHOIS）、ヘッダー、最後に公開した版とのファイルの照らし合わせを毎月行い、月1回報告します（Cloudflare Pages・Netlify に置いた場合）。脆弱性の知らせは、IPA の重要なセキュリティ情報（緊急対策情報を含む）と JVN、WordPress のときは Wordfence Intelligence を、平日に毎日自動で集めて確かめます。サイトごとに使っている物と版の一覧を持って照らし合わせ、当てはまるもののうち、CVSS 7.0以上（出どころの値。v3.1 と v4.0 で違うときは高い方）か、悪用が確認されたもの（IPA の緊急対策情報・CISA KEV）は、見つけてから1営業日以内にお知らせして対応を始めます。7.0未満は月1回の確認で扱います。静的なページでは、Cloudflare・Netlify・ドメインの会社のセキュリティのお知らせのうち、利用者側の対応が要ると書かれたものを、同じく1営業日以内にお知らせして対応を始めます。
していないこと
侵入テスト（ペネトレーションテスト）や、ネットワーク機器の設定の診断は行っていません。ここに書いたのは、作りと設定で入口を減らす範囲の話です。

ご相談の仕方

お届けした手紙やメール、この見本をご案内した窓口への返信で大丈夫です。「30分の点検を」とだけ書いていただければ、日にちの候補をお送りします。ホームページのことでも、メールやパソコンのことでも構いません。

30分の点検で分かること：外から見える範囲での、ホームページの https と安全のためのヘッダーの有無、偽メール対策（SPF・DMARC）の設定の有無、直す順番。中の設定は外からは分からないので、そこは画面を一緒に見て確かめます。
